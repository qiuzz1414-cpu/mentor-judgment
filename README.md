# mentor-judgment

> 把一位导师的判断方式，沉淀成一个可以反复调用的 Skill。
> A reusable pattern for turning your advisor's judgment into an executable checklist.

---

## 这是什么

一个 ZCode / Claude Code Skill。它做两件事：

1. **判断**——「这个方向值不值得做」「这篇论文能不能跟」「他会不会点头」
2. **审改**——你的科研稿、组会讲稿、对外文件，逐句逐段挑问题并给改法

核心主张：**一个人的判断是有顺序的，不是有分数的。**

大多数人误解导师的方式是「他觉得这个不好」。实际上更准确的是「他没走到那一步」——代价过不了，他根本不会听你讲深度。把这个顺序还原出来，比总结他的偏好有用得多。

## 核心结构

```
内容层（值不值得做）      形式层（该不该这么写）    论证层（论文怎么写）
   ① 代价                     F5 抽象层次              P1 七步论证链
   ② 确定性                   F1 一条主线              P2 贡献列表句式
   ③ 可验                     F2 每句有信息量           P3 摘要五句
   ④ 深度                     F3 信息落到「能拿它干嘛」  P4 标题模式
                              F4 图的四步法            P5 图表职责
                              F6 不交给 AI 写          P6 结构复用
```

**为什么分三层**：同一个人对不同事情的判断标准不一样。「代价太大」是内容判断，「这句没信息」是形式判断，「这里缺一步原则」是论证判断。混在一起，三边都会失准。

**一个值得注意的发现**：论证层不是新标准，而是**四问的书面形态**——他批评文献用的四把刀，恰好对应内容层的四个维度。

| 批评的刀 | 典型说法 | 对应 |
|---|---|---|
| 机制刀 | “fails to refine the strategies based on…” | 深度 |
| 前提刀 | “impractical to obtain the gradient in real-world” | 代价 |
| 参数刀 | “the penalty factor is problem dependent” | 代价 |
| 验证刀 | “only six test problems, hard to verify” | 可验 |

也就是说，**一个会判 idea 的人，写 Related Work 时用的是同一套尺子**。这是这个 Skill 最省事的地方：学一次，三处通用。

**为什么四问要逐级终止**：

```
代价高 ──→ 直接否，后面不问
  ↓
确定性低 ──→ 倾向否
  ↓
可验说不出 ──→ 倾向否
  ↓
才轮到深度和「能不能刷掉别人」
```

如果做成加权平均，结论会失真——一个代价极高的想法，不应该因为「深度够」而拿到及格分。

## 四条设计原则

### 1. 规则必须挂在原话上

`hard-rules.md` 里每条规则都能往回指到 `evidence.md` 的一句原话。没有原话支撑的判断，输出必须标 `[外推]`。

**理由**：不挂原话的规则，会退化成「要具体」「要有逻辑」这类正确但无用的建议。那正是这个 Skill 想避免的东西。

### 2. 证据分三级，只有 L1 能当依据

| 级别 | 来源 | 能用来做什么 |
|---|---|---|
| **L1** | 本人亲笔、现场原话 | ✅ 唯一的判断依据 |
| **L2** | 从其研究轨迹推断 | ❌ 只能解释动机 |
| **L3** | 第三方转述 | ❌ 只能解释情境 |

**理由**：转述会失真。同门口中的「他喜欢有进展的东西」是二手观察，不能用来预测他对某个具体 idea 的反应。

### 3. 语料库只追加，不重构

新听到原话 → 往 `evidence.md` 追加一条 → 在规则文件里加一行指针。

**理由**：这是让 Skill 能长期活着的唯一方式。每次重构都会丢掉之前积累的证据。

### 4. 本人写的东西，是最高信度的证据

这一条来自一次迭代的发现：与其揣摩一个人的判断，不如**直接读他写的论文**。

论文是他反复斟酌、投出去、被审过的产物。里面每一个「However,」都经过推敲，比任何口头表达都更能反映他的思维骨架。而且它有一个口头内容没有的好处——**你能看到完整结构**，不是碎片。

反推出来的 `paper-logic.md` 直接揭示了三点：

- 他批评文献从不停在结果层（「精度不够」），一定落到机制层
- 他在给方法之前，先确立一条「应当遵循的原则」
- 他的贡献条目第一条常常不是方法，是问题本身

这三条**从任何转述里都得不到**。

**所以如果你要移植这个 Skill**：先去找你导师自己写的东西——论文、项目书、评审意见。这些比录音、比同门口述都可靠得多，而且完全不需要额外收集什么。

## 怎么改成你自己的导师

这个仓库是一个**范本**，不是某个人的档案。要换成你自己的导师：

1. **换语料**：把 `evidence.md` 全部替换成你手头已有的书面材料——论文修改意见、邮件批复、他自己写的文章与总结、组会 PPT 上的要求。**不需要为这件事额外去记录或留存任何东西**；平时正常沟通里已经给你的东西，足够用了。
2. **改规则**：`hard-rules.md` 和 `form-rules.md` 里，他没有的规则删掉，有的补上。每条必须挂到证据。
3. **改闸门顺序**：`value-function.md` 里的顺序不是普适的。有的导师是深度优先（问题够真就做，贵也做），有的是可行性优先。**顺序错了，结论会完全相反。**
4. **跑测试**：拿三份你自己的真实稿件试，看它能不能说出你没想到的问题。

**判断做对了没有的标准**：它能否说出你**没想到**的问题。如果说出来的全是「建议更具体一点」这种话，说明规则还是通用建议，没落到这个人身上。

## 边界

这个 Skill **不做**三件事：

- **不判情绪**：会不会发火、这句话该不该当真——这些不进判断链
- **不替对方下指令**：输出写「他大概率会认为 X」，不写「他会让你做 Y」
- **不编原话**：引不到就写「此条无原话，属外推」

第三点是底线。一个会编造别人想法的工具，比没有工具更危险。

## 安装

```bash
git clone https://github.com/<your-name>/mentor-judgment.git ~/.zcode/skills/mentor-judgment
```

重启客户端后生效。之后说「他会不会否这个方向」或「帮我看看这份稿」就会触发。
