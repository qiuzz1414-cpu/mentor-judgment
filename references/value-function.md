# 价值函数：四问的判定细则

> 四问不是打分表，是**逐级终止的闸门**。顺序不可换。

---

## 为什么有优先级

对方的注意力是有成本的。原话（C-16）：

> 「感觉你们做完之后，我还得重新再去搞一遍，还是会比较占时间。」

所以真实决策顺序是：**先排除代价高的 → 再排除不可靠的 → 剩下的才谈深度**。

一个方向再深，代价高他也不会听。这就是为什么深度在最后。

---

## 闸门一：代价

**他实际在问**：这件事要花多少时间、算力、钱？值不值？

**来源**：R1｜C-07

| 档 | 判据 | 典型信号 |
|---|---|---|
| **低** | 现有资源几小时内可验证 | 仿真、小模型、单卡、不买设备 |
| **中** | 需排队/需几周/需小额采购 | 多卡训练、要标数据、要买传感器 |
| **高** | 需大额投入且无着落 | 训大模型、大规模采集、买昂贵硬件且预算无着落 |

**判定后的动作**：

- 低 → 进闸门二
- 中 → 进闸门二，但**结论里必须写「他大概率会计较这笔钱」**
- 高 → **终止**，输出：「代价太大 — 按 R1 推断，他会认为先要把这笔账算清楚才谈技术」

**例外**：代价高 + 确定性极高 → 可以过。他接受「贵但稳」。

---

## 闸门二：确定性

**他实际在问**：出错的时候能不能兜住？

**来源**：R2｜C-08

| 档 | 判据 | 典型信号 |
|---|---|---|
| **高** | 有约束保证、有可行解判定、可回滚 | 规划/搜索/优化；有 fallback；失败可检测 |
| **中** | 有兜底但兜底本身也不完美 | 有检测机制但无保证；有 baseline 可退 |
| **低** | 端到端黑箱，失败不可预知 | 端到端策略网络；不可解释；无 fail-safe |

**判定后的动作**：

- 高 → 进闸门三
- 中 → 进闸门三，结论注明「需要说明 fail-safe」
- 低 → **倾向否**，输出：「能做，但他大概率会担心不可执行」

**原话对照**：「跑不掉的」= 高；「有幻觉的」= 低。

---

## 闸门三：可验

**他实际在问**：拿什么证明它有效？

**来源**：R3

| 档 | 判据 | 典型信号 |
|---|---|---|
| **高** | 量化指标 + 可比 baseline + 可复现 | 「比 X 高 5 个点，代码开源」 |
| **中** | 有指标无 baseline | 「跑通了，效果还行」 |
| **低** | 只有 demo | 「视频看着挺酷」 |

**判定后的动作**：

- 高 → 进闸门四
- 中 → 进闸门四，结论要求补 baseline
- 低 → **倾向否**

---

## 闸门四：深度 + 能否刷掉

**他实际在问**：这是真问题吗？做出来能不能干掉别人？

**来源**：R4 + R5｜C-09 / C-10

### 深度

| 档 | 判据 |
|---|---|
| **高** | 抓住领域公认难点，且说清为什么难 |
| **中** | 改进了已有方法，但没说清为什么需要改 |
| **低** | 套壳：换个场景重跑 |

### 能否刷掉

| 档 | 判据 |
|---|---|
| **能** | 至少一个维度明确优于现有路线 |
| **勉强** | 同水平但更便宜/更快 |
| **不能** | 只是「也做出来了」 |

**两维合成结论**：

```
深度高 + 能刷掉  → 点头
深度高 + 勉强    → 看情况（他会问「那你的优势是什么」）
深度中 + 能刷掉  → 看情况（有优势但问题不够真）
深度低 + 不能    → 否
```

---

## 完整判定表

| 代价 | 确定性 | 可验 | 深度 | 能否刷掉 | 结论 |
|---|---|---|---|---|---|
| 高 | — | — | — | — | **否**（不到下一关） |
| 中 | 低 | — | — | — | **否** |
| 中 | 中 | 低 | — | — | **否** |
| 中 | 中 | 中 | 高 | 能 | **看情况**（要补 baseline） |
| 低 | 高 | 高 | 高 | 能 | **点头** |
| 低 | 高 | 中 | 高 | 勉强 | **看情况** |

## R6 的插入位置

在闸门一之前，先过一遍 R6：

```
① R6：这件事归学还是归算？
   ├─ 用错工具 → 代价和确定性必然是坏的 → 直接引 R6 否掉，不必走四问
   └─ 用对工具 → 进四问
```

**为什么**：工具错了，四问会得出「代价高+确定性低」的结论，但那是表象。引 R6 更准，也更能说服对方——他会认同「这问题本来就不该用学来做」，而不是「你觉得太贵」。

## 三种对象的输入提取

判断标准不变，只换提取项：

### 方向与 idea

```
① 要做什么（一句话，不含手段）
② 投入多少：时间 / 算力 / 钱
③ 怎么算成功（可量化的判据）
```

缺 ③ 就无法判深度，追问。

### 别人的工作（论文/项目）

```
① 它解决了什么问题
② 用什么手段（学 / 算 / 混合）
③ 比 baseline 强在哪（数字）
```

缺 ③ 就无法判 R5，追问。

### 自己的产出（汇报/文档）

```
① 主线一句话
② 支撑证据（数字）
③ 你要对方做什么决定
```

缺 ③ 说明这份东西没有目的——先补目的再审。

---

## 输出的固定格式

```
【第一反应】他会先问的那一个问题（一句话，用对方的关注点）
【四问判定】
  代价   ███░░  高/中/低 — R1｜L1
  确定性 ██░░░  高/中/低 — R2｜L1
  可验   ███░░  高/中/低 — R3｜L1
  深度   ████░  高/中/低 — R4｜L1
【他会认可的】具体哪个角度（要能追到原话）
【他会否掉的】具体哪句话（要能追到原话）
【结论】点头 / 否 / 看情况 + 一句话条件
【层级】你现在在第 N 层（只定位，不参与判断）
```

**条数控制**：整体 300 字内。超过说明在注水（违反 F2）。

## 常见误用

| 误用 | 问题 | 正确做法 |
|---|---|---|
| 四问各打一个分取平均 | 他不是加权平均，是逐级排除 | 逐级终止 |
| 代价高但仍然详细分析深度 | 浪费，他不会听到那里 | 终止 |
| 「他会觉得不错」 | 无依据，违反可信度规则 | 引原话或标 `[外推]` |
| 用 L3（第三方转述）下判断 | 可靠度不足 | 只能解释情境 |
| 编造对方的评价 | 最严重 | 引不到就写「此条无原话」 |
