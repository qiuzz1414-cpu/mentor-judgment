# 论文论证逻辑（P1–P6）

> 来源：反推自某人 2017–2026 年的 9 篇论文（从应用数学期刊到本领域顶刊）。
> 这是**最高信度证据**：不是转述他的想法，是直接读他怎么写。
>
> **核心发现**：他批评文献用的四把刀，就是内容层四问。论文层不是新标准，是四问的书面形态。

---

## 最重要的一条：批评 = 四问

Related Work 里他从不说「效果不够好」。每次都落在**具体的机制、前提或验证**上：

| 刀 | 实际写法 | 对应 |
|---|---|---|
| **机制刀** | 「relied on the generation of...」/「fails to refine the strategies based on how changes affect...」 | R4 深度 |
| **前提刀** | 「normally impractical to obtain the required gradient information in real-world problems」 | R1 代价 |
| **参数刀** | 「an important drawback is that the penalty factor is problem dependent」 | R1 代价 |
| **验证刀** | 「the studies were only carried out on six test problems, thus it is hard to verify its effectiveness」 | R3 可验 |

**句式固定**：

```
X 提出了 A [n]。However, [具体的缺陷]。
```

一篇里出现 9 次「However」不是修辞，是**逐条拆解**。他从不批量否定，一次只拆一个。

**红线**：如果你写「现有方法精度不够」——这不是批评，是抱怨。要写到「它在哪一步做不到、为什么做不到」。

---

## P1 Intro 的七步论证链

按顺序，缺一步就读起来「没深度」：

```
① 问题类 + 为什么重要
     「这类问题在现代工程系统中频繁出现 [1]-[3]。」
② 一个具体实例（不要泛泛举例）
     「一个典型应用是 … 」
③ 现有方法分几类，各在做什么
     「当前方法主要采用 … 」
④ 逐条批评：X 做了 A。However, [机制缺陷]。   ← 可重复多次
⑤ 归纳共同失败点（机制层，不是结果层）
     「这些方法未能基于 … 去调整策略」
⑥ 提出应当遵循的原则（此时还没给方法）
     「策略应当根据 … 的变化来选取」
⑦ 才给方法 + 贡献列表
```

**第 ⑤→⑥ 这两步是他和多数人的分水岭。**

多数人从「现有方法失败」直接跳到「所以我提出 X」。他要先说出**一条应当遵循的原则**，再让方法去满足它。这样方法就有了必然性，不是拍脑袋。

---

## P2 贡献列表的句式

**统一用被动式，不用 we**：

```
A [名词短语] is proposed / introduced / developed / investigated / formulated
  to [目的从句].
```

**三条规律**：

1. **第一条常不是方法，是问题**——「A problem for X is investigated」。先把问题建立起来，再讲怎么解。
2. **每条必须带 `to` 目的**：做了什么 + 为了什么。缺后半句就只是罗列。
3. **每条只讲一件事**。一条里塞两个贡献，说明没想清楚。

### 最高形态：第一条是原则，不是方法

他顶刊那篇的第一条贡献长这样：

> 「本研究**确立**了：这类策略**应当**依据种群特征的退化情况来自适应选取。」

贡献不是「我提了个方法」，是「**我确立了一条判断标准**」。

这是最难被拒的写法——审稿人可以否定你的方法，很难否定你的问题定义。

## P3 摘要的五句结构

| 句 | 功能 | 句式 |
|---|---|---|
| 1 | 场景 | 「X 被用于 … 」 |
| 2 | **缺口** | 「**Most of the current works** 优化了 … **while neglecting** … 」 |
| 3 | **动机** | 「**This motivates us to** study … 」 |
| 4 | 做法 | 「A … **is formulated** … we present a … 」 |
| 5 | 结果 | 「**experimental results demonstrate that compared with the existing works**, our scheme … 」 |

**第 2 句是全篇的枢纽**：`Most of the current works ... while neglecting ...`。

这一句定生死——它决定了你的工作有没有存在的理由。

**第 5 句必须带对比**：`compared with the existing works`。没有对比的结果不是结果。

## P4 标题模式

他的标题几乎都是同一个语法骨架：

```
[限定语] 核心对象 for 应用场景 : 子问题 A and 子问题 B
```

**两个可学的点**：

1. **`for` 是核心连接词**：左边是你做什么，右边是给谁用。左边写不出方法、右边写不出场景，标题就不成立。
2. **把方法哲学塞进标题**：他有一篇用了 `Feasibility-Driven`（可行解驱动）这个词。这不是修饰词，是他整套判断（R2 确定性优先）的浓缩。

**自查**：你的标题里有没有这样一个词，能让人一眼看出你的立场？

## P5 图与表的论证职责

每张图都在承担论证，不是装饰：

- **框架图**：必须能一眼看出「哪一层归学、哪一层归算」——这是 R6 的可视化
- **对比曲线**：必须带 baseline 和具体指标，不是「我们的更好」
- **场景图**：必须标注约束在哪，因为约束往往是整条研究线的起点

**检查**：把你的图去掉文字，只看图形，能不能说出结论？不能，说明图没在论证。

---

## P6 与研究轨迹的关系

**L2 观察**：这个人的研究内核近十年没变，只换应用载体。

写作上的表现是：**Intro 的 ①②③ 步每篇都换，④⑤⑥ 步的语法完全一样。**

也就是说，他换的是**场景和 baseline**，不换**论证结构**。这也是「一条主线」在论文层的形态——不是内容重复，是**结构复用**。

**启发**：写第二篇论文时，最省力的不是换题目，是沿用上一篇的论证骨架，只换 ①②③ 和 baseline。

## 论文模式下的输出格式

```
【论证链体检】
  ① 问题类      ✓/✗
  ② 具体实例    ✓/✗
  ③ 现有方法分类 ✓/✗
  ④ 逐条批评    n 条，其中机制层 n / 结果层 n ← 结果层的要改
  ⑤ 共同失败点  ✓/✗（机制层还是结果层？）
  ⑥ 应当遵循的原则 ✓/✗  ← 最常缺的一步
  ⑦ 方法与贡献  ✓/✗

【贡献条目体检】
  条数 n｜带 to 目的 n/n｜被动式 n/n｜第一条是否建立问题 ✓/✗

【摘要五句体检】
  场景 ✓｜缺口 ✓｜动机 ✓｜做法 ✓｜对比结果 ✓
```
