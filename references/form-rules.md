# 形式规则 F1–F6（写作层）

> 全部挂 L1 原话（见 `evidence.md`）。用在：科研稿、组会讲稿、对外交付文件。

---

## F5 抽象层次匹配听众 —— 总闸

**规则**：动笔前先问「给谁看」。抽象层次决定主线怎么切。

**原话**（C-02 / C-22 / C-24）：
> 「这里会涉及到表达的对象，所预定的逻辑层次（考虑对象的知识能力），表达的主线逻辑结构。」
> 「你主线这个取决于你的抽象层次。」
> 「里面的硬件实现……其实我们根本就不讲了……论文是不会写的。」

**判据**：**抽象层次 = 你砍掉哪一层**。

| 听众 | 留什么 | 砍什么 |
|---|---|---|
| 导师 | 领域脉络、结论、机会、决策点 | 实现细节、参数、调试过程、底层原理 |
| 组内同学 | 主线 + 关键方法 + 踩过的坑 | 领域背景（他们知道） |
| 外部/评审 | 背景、问题定义、方法、量化结果 | 内部术语、非关键实验 |

**注意「载体也决定层次」**：同一份内容，口头讲可以讲实现细节，写进论文就不能。他原话是「我们在这里你可以讲一下……但是他论文是不会写的」。

## F1 一条主线

**规则**：从输入讲到输出，一条线到底；支线顺带提，不打断主线。

**原话**（C-20 / C-21）：
> 「我们就按照一条主线……主线不变。但是支线的时候你就顺带提一下就好了，主次之分也要有。」
> 「应该是有一条主线的。但主线首先这条主线的逻辑是要讲清楚的。」
> 「就是总分，然后还有就是章节之间的那个关系的连接。」

**三个子要求**：

1. **能一句话说出主线**：说不出来 = 没有主线
2. **总分结构**：先给骨架，再进细节
3. **章节之间要有连接**：不是罗列，是「因为 A 所以 B」

**反例**（典型被批的写法）：

```
✗ 我们用了 A 相机。深度通过视差计算，16 位编码，30fps。
  然后我们用 B 算法建图。然后我们用 C 算法规划。
  然后我们用 D 做控制。
```
问题：每句都对，但**没有线**。读者不知道为什么要按这个顺序。

```
✓ 主线：感知 → 定位 → 建图 → 规划 → 控制，每一环都受上一环的误差约束
  · 感知：30fps 深度，误差 ±2cm —— 决定了定位精度上限
  · 定位：视觉里程计累积漂移 —— 所以必须有建图做回环修正
  · 建图：2fps —— 太慢，只用于建图不用于实时定位（这就是为什么要分开）
  · 规划：在 0.05m 栅格上跑 —— 受地图精度限制
  · 控制：10Hz —— 受规划频率限制
```

**检验方法**：把每段第一句抽出来连读，如果读得通，主线成立；读不通，主线断了。

## F2 每句都有信息量

**规则**：每句话要么给数字，要么给结论。**报动作不算信息**。

**原话**（C-16）：
> 「你这句话没啥信息，你这句话没必要讲。在写论文的时候也是。」
> 「你每次讲东西我感觉我信息量还是比较少。」

**他的判据**：不是「说得对不对」，是「**我还得重新再搞一遍**」——增加对方负担的话就是废话。

**句式对照表**：

| ✗ 没信息（报动作） | ✓ 有信息（给结论） |
|---|---|
| 我们使用了 X 算法进行建图 | X 建图约 200MB，2fps —— 慢于相机 30fps，故只用于建图不用于定位 |
| 我们对参数进行了调优 | 调完后超调从 15% 降到 3%，稳态误差 <1cm |
| 实验结果表明方法是有效的 | 3 个场景成功率 78.3%，baseline 51.7%，提升 26.6 个点 |
| 该模块负责数据预处理 | 把 30fps 原始流降到 10fps 特征流，带宽从 120MB/s 降到 8MB/s |
| 我们对比了多种方案 | 对比 4 种方案，只有 A 在 <100ms 内给出可行解，其余都超时 |

**最容易犯的三类废话**：

1. **报名字**：「我们用了 YOLO」→ 要问：多大模型？多少 FPS？mAP 多少？
2. **报过程**：「我们反复调试」→ 要问：调了什么？调到多少？
3. **报态度**：「效果较好」→ 要问：好多少？跟谁比？

## F3 每条信息落到「能拿它干嘛」

**规则**：给完信息，加一句小结论，说明它跟当前任务的关系。

**原话**（C-18 / C-19）：
> 「主要是要讲跟现在要做的一个联系，可能也不一定说是联系，可能要加一个小结论。」
> 「我看完了这个东西之后，我觉得他用来做什么？」

**结构**：`[信息] → [所以] [对我当前任务意味着什么]`

**例子**：

```
✗ 某小模型是 450M 参数，可以在消费级 GPU 上训练。
✓ 某小模型是 450M 参数，消费级 GPU 可训 —— 意味着组内现有显卡就能跑，
  不用等预算批下来。
```

```
✗ 仿真到现实的抓放成功率从 90% 掉到 60–75%。
✓ sim→real 抓放从 90% 掉到 60–75% —— 意味着纯仿真结论不能直接写进论文，
  必须留真机验证的一环。
```

**判断标准**：把「所以…」那半句删掉，如果读者还要自己推，就是漏了 F3。

## F4 图的四步法

**规则**：讲任何一张图，四步不能缺：是什么 → 有什么元素 → 怎么看 → 什么结论。

**原话**（C-17）：
> 「我肯定要说一张图是啥，对吧？……然后里面的元素有哪一些，然后再具体说说这个东西我们怎么看，得到什么一个结论呢？」

**四步模板**：

```
① 是什么   「这是 XXX 的建图结果」
② 有什么   「红色是估计轨迹，灰色是障碍点云，蓝色框是回环检测位置」
③ 怎么看   「轨迹越贴合走廊中线越好；回环处出现折角说明修正不连续」
④ 结论     「三处回环都闭合，最大偏差 12cm，说明建图精度够用于规划，
             但折角说明回环权重偏高，需要调」
```

**常见缺失**：只做 ①②，跳过 ③④。这是最常被挑的。

**论文里的图**：图注要能独立读懂 = ②③④ 全在图注里。

## F6 不交给 AI 写

**规则**：内容必须自己消化后重写。AI 可以帮结构，不能帮内容。

**原话**（C-25）：
> 「不要纯 AI 去总结写，那 AI 的逻辑思路还是太弱了。」

**为什么**：AI 写的东西 F1（主线）和 F3（挂钩）必然弱——它不知道你的任务是什么，只能堆信息。这正好是最容易被挑的两点。

**操作约束**：

- 生成模式只出**骨架 + 句式**，内容留 `〔待你填〕`
- **不编数字**。没有数据就写 `〔数据〕`
- 审改时发现整段像生成 → 标出来，要求重写而不是小修

**自检**：随便挑一句，问「这句话如果换个课题还成立吗？」——成立，说明是空话（F2/F3 不过）。

## 审改顺序

```
① F5 给谁看 → 定抽象层次
② F1 抽首句连读 → 主线断没断
③ F2 逐句过 → 标「没信息」+ 改法
④ F3 查每条信息后面有没有「所以」
⑤ F4 查每张图四步齐不齐
⑥ F6 扫一遍有没有整段 AI 味
```

**为什么 F5 在最前**：层次错了，后面全部白改。给导师的东西砍实现细节是对的；给外部的东西砍了背景就是错的。

## 输出格式

```
〔位置〕原句
  F# ✗ 判定 —— 缺什么
  改法：……

—— 总计 ——
F1 断 2 处｜F2 命中 7 句｜F3 缺 4 处｜F4 图 2 张不完整｜F6 1 段疑似生成
```

**改法必须给可用句子**，不给「建议更具体一些」这种空话——那本身就是 F2 违规。
