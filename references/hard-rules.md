# 硬规则 R1–R6（内容层）

> 每条挂 L1 原话（见 `evidence.md`）。**置信度标注是硬性要求**：没有 L1 支撑的判断，输出里必须标 `[外推]`。

---

## R6 学 / 算的边界 —— 总枢纽

**规则**：任何工作先问一句——这件事该由「学」解决，还是该由「算」解决？

- **学**（深度学习 / 大模型）：场景理解、语义、感知、多模态
- **算**（优化算法 / 规划 / 搜索）：优化、约束满足、可行解

**原话**（C-06）：
> 「深度学习他的能力在哪里？它在于场景的理解和感知。算法它在于优化。因为我们所有训练出来的模型是一个 FS，而算法求的是 FS 最优解。两个是不一样的。」

**判定表**：

| 问题性质 | 该用什么 | 用错了他会怎么说 |
|---|---|---|
| 需要理解「这是什么」 | 学 | 用算硬做 → 「做语义理解或图像理解比较差，比不过」（C-11） |
| 需要「在约束下找最优」 | 算 | 用学硬做 → 「代价非常大，而且还有风险，还不一定执行的好」（C-07） |
| 两者都有 | **分层**：上层学、下层算 | 混在一起 → 「说不清它到底在解决什么」 |

**为什么它是总枢纽**：R1–R5 全部由它派生。代价高是因为用错了工具；确定性低是因为让学去做算的事；深度不够是因为没想清楚这问题归谁。

**派生关系**：

```
R6 这件事归学还是归算
 ├─ 用错工具 → R1 代价高 / R2 确定性低
 ├─ 用对工具 → 才有资格谈 R3 可验、R4 深度
 └─ 用对且更深 → R5 刷掉别人
```

## R1 代价优先

**规则**：先算代价（时间、算力、钱、人力），代价不划算就不讨论技术优劣。

**原话**（C-07）：
> 「我觉得我们要从代价的角度上，因为你知道这样的一个模型代价非常大，而且他还有风险，还不一定执行的好。」
> 「如果说我同样的时间……我们可以做到 100 毫秒内，我们就搜索出一个东西来，那我觉得是可以的。」

**判定阈值**：

| 代价 | 判定 | 说明 |
|---|---|---|
| 低 | 可接受 | 仿真即可验证、能用现有卡、几小时出结果 |
| 中 | 需解释 | 要排队等卡、要几周、要买设备 |
| 高 | **直接终止** | 要训大模型、要采集大规模数据、要新硬件且预算无着落 |

**关键**：他接受「代价高」的唯一条件是**确定性同时很高**。代价高 + 有幻觉 = 直接否。

**操作**：说服他的唯一方式是**给数字**。他原话里用的是「100 毫秒」这种具体门槛，不是形容词。

## R2 确定性优先于性能

**规则**：能保证「可行解」的，胜过「可能更好但可能崩」的。

**原话**（C-08）：
> 「一旦我是可行解，我这个解就是可以执行的……只要他找到可信的那个解，就一定是可执行的，这是跑不掉的。但是那个 AI 它是有幻觉的。」

**判定阈值**：

| 确定性 | 判定 |
|---|---|
| 高 | 有约束保证 / 有可行解判定 / 可回滚 |
| 中 | 有 fallback，失败可检测 |
| 低 | 端到端黑箱，失败不可预知 |

**强判断词**：「跑不掉的」= 认可的确定性；「有幻觉的」= 否定的不确定性。

---

## R3 可验性

**规则**：拿不出验证方法的，不算工作。

**原话**（C-07 / C-14 语境 + 现场）：
> 「这个东西好验证。」
> 「拿尺子实测轨迹误差。」（对视觉里程计漂移的处置意见）

**判定阈值**：

| 可验 | 判定 | 表现 |
|---|---|---|
| 高 | 有量化指标 + 可复现 + 有 baseline | 能说「比 X 高 5 个点，代码开源」 |
| 中 | 有指标但无 baseline | 只能说「跑通了，效果还行」 |
| 低 | 只有 demo 视频 | 「看着挺酷」 |

**隐藏标准**：「效果一般」不算结论。要的是**数字和对比**。

---

## R4 深度决定投稿命

**规则**：问题看得越深，论文越好发。深度 = 有没有抓住真 gap。

**原话**（C-09 / C-14）：
> 「就看我每个人对问题看的深浅，我看的越深，我的论文很好送的。」
> 「我们不要太将就，还是追求一下，把这个东西给它做深或者做好了。」

**判定阈值**：

| 深度 | 判定 | 表现 |
|---|---|---|
| 高 | 抓住了领域公认的难点，且说清了为什么难 | 能一句话说出「大家都在绕，但绕不过去的是 X」 |
| 中 | 改进了已有方法，但没说清为什么需要改 | 「我加了注意力机制，效果提升 2%」 |
| 低 | 套壳：换个应用场景重跑 | 「把 A 用到 B 上」 |

**判据**：能到第三层（凝练 gap）才算有深度（C-01）。只讲清一篇 = 第一层，不够。

## R5 能不能刷掉别人

**规则**：做出来能不能干掉现有技术路线。**只做到「差不多」= 没做**。

**原话**（C-10）：
> 「如果我们有更好的技术路线，其实我们可以把它刷掉。我们也可以说，我们局部路径我们也能干掉你。」

**判定阈值**：

| 能不能刷掉 | 判定 | 表现 |
|---|---|---|
| 能 | 有明确的技术路线优势 | 「规划可保证可行解，端到端不能」 |
| 勉强 | 同水平但更便宜/更快 | 「精度一样，速度 5 倍」 |
| 不能 | 只是「也做出来了」 | 「我们也复现了」 |

**注意**：R5 不是要求全面超越，是要求**有一个维度能明确干掉对方**。原话里说的是「局部路径我们也能干掉你」——局部赢也是赢。

## 组合规则

**四问不是四个并列打分，是逐级终止**：

```
R1 代价 ──高──→ 终止，不看后面
   ↓可接受
R2 确定性 ──低──→ 倾向否
   ↓可接受
R3 可验 + R4 深度 + R5 ──→ 完整评估
```

**R6 在四问之前先过一遍**：先判归学还是归算，再谈代价。工具用错了，代价和确定性必然是坏的——这时直接引 R6 比引 R1/R2 更准。

**没有 L1 支撑时**：标 `[外推]`，并写出「由 R_ + R_ 组合推断」。例：

```
【结论】[外推] 他倾向否
【推导】R6（该归算的事用学做）+ R1（代价高）+ R2（有幻觉）三者叠加
```

## 定制提醒

换导师时，**这六条要重新校验**：

- 并非每个导师都把「代价」放第一位。有的导师是深度优先（只要问题够真，贵也做），有的是可行性优先（先能跑起来再说）。
- 顺序错了，结论会完全相反。
- 方法：把你导师过去否定过你/别人的十个理由翻出来，按出现频率排序，那就是他真实的闸门顺序。
